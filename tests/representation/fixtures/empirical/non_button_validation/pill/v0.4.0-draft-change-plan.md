# v0.4.0-draft — Implementation-Ready Change Plan

**Status:** PROPOSED. Not implemented. Awaiting owner approval.
**Baseline:** `component-representation-contract v0.3.1-draft` — must remain byte-unchanged until approval.
**Evidence base:** Pill R-2 reconciliation (`NAME-0002/non_button_validation/pill/`) + the accepted Buttons baseline.

Design rules for this plan:

- **Component-neutral.** No enum member, field, or default may name a component type.
- **Typed, referentially validated.** No magic strings, no unexplained enum members like `single_component` or `__treatment__`. Every dimension and every scope is a tagged object whose references the validator resolves.
- **Recomputable over asserted.** Where the contract makes a structural claim, the validator must be able to re-derive it from evidence and reject a mismatch.
- **Migration-complete.** Every breaking change ships a mechanical migration for the accepted Buttons baseline plus regression fixtures.

## 2. C-1 — `layoutRepresentations[]`

Removes the single-value bottleneck. Each representation is independently scoped to its own evidence nodes and its own schema variants / component sets.

```jsonc
"layoutRepresentations": [
  {
    "representationId": "LR-1",                    // ^LR-[0-9]+$
    "strategy": "list",                            // matrix | list | scenario_gallery
    "appliesTo": {
      "schemaVariantIds": ["PSV-1"],
      "componentSetIds": ["NODE-0037", "NODE-0035", "NODE-0036", "NODE-0038"]
    },
    "evidenceNodeIds": ["NODE-0046", "NODE-0345"],
    "allocation": null,                            // required iff strategy == "matrix"
    "evidence": { /* evidenceRecord */ }
  },
  {
    "representationId": "LR-2",
    "strategy": "matrix",
    "appliesTo": { "schemaVariantIds": ["PSV-1"], "componentSetIds": [ /* 4 */ ] },
    "evidenceNodeIds": ["NODE-0047", "NODE-0051"],
    "allocation": { /* see C-2 + C-4 */ },
    "evidence": { /* evidenceRecord */ }
  }
]
```

**Rules.**

- `minItems: 0`. An empty array is the honest representation of "no documentation" — which is exactly PSV-2's situation.
- `allocation` is required iff `strategy == "matrix"`, and must be absent otherwise (replaces the v0.3.1 top-level `allOf` and CV-9).
- **CV-3's "exactly one allocation per variant" rule is deleted.** It encoded the assumption that every variant is documented. Replaced by **CV-3b**: every `appliesTo.schemaVariantIds` / `componentSetIds` entry must resolve, and a variant covered by *zero* representations is legal but must appear in a new required `undocumentedSchemaVariantIds[]` at top level, so silence is explicit rather than accidental.

**Pill result:** LR-1 (list, PSV-1), LR-2 (matrix, PSV-1), `undocumentedSchemaVariantIds: ["PSV-2"]`. CF-1 and CV-3 both close.

## 3. C-2 — Typed dimension references

No strings, no `__treatment__`. A dimension is a tagged union, validated by `kind`.

```jsonc
"allocation": {
  "rows":    { "kind": "component_set_identity",
               "orderedComponentSetIds": ["NODE-0035","NODE-0036","NODE-0037","NODE-0038"],
               "orderingRule": "ascending_absolute_y" },
  "columns": { "kind": "variant_property", "propertyKey": "Accent",
               "orderedValues": ["Success","Error","Warning","Info"],
               "orderingRule": "ascending_absolute_x" },
  "bands":   [ { "kind": "variant_property", "propertyKey": "Size",
                 "orderedValues": ["Regular","Small"],
                 "orderingRule": "ascending_absolute_y" } ],
  "fixedFilters": [ { "kind": "fixed_filter", "propertyKey": "Icon", "value": "None" } ]
}
```

**`kind` values and their validation:**

| `kind` | Extra fields | Validator must check |
|---|---|---|
| `variant_property` | `propertyKey`, `orderedValues`, `orderingRule` | `propertyKey` is declared **VARIANT** in *every* referenced schema variant; every `orderedValues` entry is in that property's `canonicalOptions` |
| `component_set_identity` | `orderedComponentSetIds`, `orderingRule` | every id resolves to a `componentSets[].id`, and each is within the representation's `appliesTo` |
| `fixed_filter` | `propertyKey`, `value` | `propertyKey` is declared in every referenced variant; `value` is a legal option; the evidence shows exactly this one value |

`orderingRule` enum: `ascending_absolute_x`, `ascending_absolute_y`, `declared_variant_option_order`, `document_order`.

**CV-7 is rewritten** to dispatch on `kind` instead of assuming `variant_property`. Pill's row dimension becomes legal *and* checkable. PB-2 closes.

## 4. C-3 — Typed finding scope

Retires the Button-hardcoded vocabulary without inventing an unexplained replacement. `generalizationScope` (a flat enum) becomes a two-field reference that the validator resolves.

```jsonc
"structuralFindings": [
  { "findingId": "PF-03",
    "scope": { "scopeType": "schema_variant", "scopeRef": "PSV-1" },
    "corroboration": { "level": "single_component_observed", "corroboratingContractIds": [] },
    "description": "...", "evidence": { /* … */ } }
]
```

`scopeType` enum — each value names the array whose ids `scopeRef` must resolve against:

| `scopeType` | `scopeRef` resolves to |
|---|---|
| `node` | a Figma node id appearing in this contract |
| `component_set` | `componentSets[].id` |
| `schema_variant` | `propertySchemaVariants[].variantId` |
| `semantic_family` | `semanticFamilies[].familyId` |
| `contract` | this document's `contractId` |
| `cross_contract` | a contract id listed in `corroboration.corroboratingContractIds` |

`corroboration.level` enum, replacing the old scope-as-strength conflation:

| Level | Meaning | Gate |
|---|---|---|
| `single_component_observed` | seen in one component, from evidence | default |
| `multi_component_corroborated` | seen in ≥ 2 contracts | requires ≥ 2 entries in `corroboratingContractIds`, each resolving |
| `owner_declared_standard` | owner has declared it | requires a resolvable `ownerConfirmations` record |

`buttons`, `observed_button_invariant`, `button_specific_pattern` and `candidate_cross_component_invariant` are **removed**. A Button finding becomes `scopeType: "contract"`, `scopeRef: "NAME-0001-buttons-…"`, `corroboration.level: "single_component_observed"`.

**Pill result:** all 20 findings get real scopes. PF-03 → `schema_variant` / `PSV-1`. PF-11 → `contract`. PF-02 → `component_set` / `NODE-0039`. CF-7 and PB-3 close.

## 5. C-4 — Recomputable allocation evidence

`allocation.evidence` becomes a required pointer to an artifact with the shape prototyped at `evidence/allocation-evidence-MA-1.json`:

```jsonc
"allocationEvidence": {
  "artifactPath": "evidence/allocation-evidence-LR-2.json",
  "artifactSha256": "…",
  "derivationMethod": "instance_variant_properties_and_geometry"
}
```

Artifact contract:

| Field | Content |
|---|---|
| `sourceDocumentationNodeIds` | the block nodes read |
| `observations[]` | one entry per in-scope instance: `instanceId`, `componentSetId`, `rowGroupNodeName`, `variantProperties` (real, from the API), `absoluteX`, `absoluteY` |
| `derivedDimensions` | rows / columns / bands / fixedFilters, each with `kind`, `orderingRule`, ordered values |
| `recomputationCheck` | cell and position counts |

**New rule CV-12.** For every matrix representation: load the artifact, verify path containment and SHA-256, then **independently re-derive** `derivedDimensions` from `observations[]` using the declared `orderingRule`s, and reject if the re-derivation does not equal the declared `allocation`. Also reject when `observations` is empty.

This is what closes the probe-B gap: a fabricated `MA-2` for an undocumented set has no observations and fails immediately, and an allocation whose axes contradict the instances fails on re-derivation. The validator stops taking allocations on trust.

## 6. C-5 — Discriminated coverage metrics

```jsonc
"coverageMetrics": [
  { "metric": "instance_placements",        "value": 40, "evidenceNodeIds": ["NODE-0041"] },
  { "metric": "unique_variant_combinations","value": 12, "evidenceNodeIds": ["NODE-0041"] },
  { "metric": "matrix_cells",               "value": 4,  "representationId": "LR-2" }
]
```

Replaces the untyped `documentedPairingCount`. `metric` enum: `instance_placements`, `unique_variant_combinations`, `matrix_cells`. `minItems: 1`; duplicate `metric` values per set rejected. `matrix_cells` requires a resolvable `representationId`.

**Pill result:** all three of Pill's real numbers become recordable and distinguishable. PB-8 closes. Buttons' `100` migrates to whichever metric the owner confirms (see §12, M-5 — this is the one migration that needs a human).

## 8. C-7 — Theme model with collection/mode provenance

Replaces the singular, mis-modelled `themeModel`.

```jsonc
"themeModel": {
  "collections": [
    { "collectionId": "VariableCollectionId:TRUNC-0005/NODE-0048",
      "collectionKey": "TRUNC-0005", "collectionName": "colors",
      "remote": true, "defaultModeId": "NODE-0027",
      "modes": [ { "modeId": "NODE-0027", "modeName": "Dark", "isDefault": true },
                 { "modeId": "NODE-0028", "modeName": "Light", "isDefault": false } ],
      "themeVarying": true }
  ],
  "containers": [
    { "containerNodeId": "NODE-0043",                     // ← identity is the id, not the name
      "containerNodeName": "card",
      "labelSourceNodeId": "NODE-0379", "labelText": "Dark Mode",
      "modeBindings": [
        { "collectionId": "VariableCollectionId:TRUNC-0005/NODE-0048",
          "resolvedModeId": "NODE-0027", "resolvedModeName": "Dark",
          "provenance": "inherited_default",
          "provenanceEvidenceNodeIds": ["NODE-0043","NODE-0380","NODE-0041","NODE-0040","NODE-0045"] }
      ] }
  ],
  "variablesUsedByDescendants": [
    { "variableId": "VariableID:TRUNC-0006/NODE-0050", "variableKey": "TRUNC-0006",
      "variableName": "System/Expressions/success", "resolvedType": "COLOR",
      "collectionId": "VariableCollectionId:TRUNC-0005/NODE-0048",
      "valuesByMode": { "NODE-0027": "#43DB70", "NODE-0028": "#17CF60" },
      "sampledOnNodeIds": ["NODE-0070","NODE-0106"], "exhaustive": false }
  ]
}
```

Three separations, matching the evidence:

1. **`collections[]`** — many collections, each with real identity and a `themeVarying` flag (`layout-scale` is recordable and marked `false`).
2. **`containers[].modeBindings[].provenance`** — enum `explicit` | `inherited_default` | `inherited_from_ancestor`, with `provenanceEvidenceNodeIds` naming the ancestry walked. Pill's Dark card is `inherited_default`; its Light card is `explicit`.
3. **`variablesUsedByDescendants[]`** — separate from container binding, with an honest `exhaustive` flag.

`boundVariableId` is **deleted**. CF-4, CF-5, CF-10 and PB-4 close.

## 9. C-8 — Typed treatment identity

```jsonc
"treatment": { "kind": "set_identity", "label": "Filled" }
// or
"treatment": { "kind": "in_set_variant_axis", "propertyKey": "Style" }
// or
"treatment": { "kind": "none" }
```

Replaces the required string `treatmentLabel`. Validator: `set_identity` requires a non-empty `label`; `in_set_variant_axis` requires `propertyKey` declared VARIANT in that set's schema variant. Pill's four visible sets are `set_identity`; `NODE-0039` is `in_set_variant_axis` / `Style` — no sentinel. CF-2 and PB-6 close.

## 10. C-9 — Non-VARIANT properties represented downstream

`propertySchemaVariants[].properties[]` gains a required `role`: `variant_axis` | `content_text` | `content_instance_swap` | `boolean_toggle`, consistent with `type`.

Then, per component set:

```jsonc
"nonVariantPropertyCoverage": [
  { "propertyKey": "Pill Value#NODE-0124", "role": "content_text",
    "declaredDefault": "Label",
    "documentedOverridesObserved": false,
    "evidenceNodeIds": ["NODE-0041"] }
```

**New rule VR-7 (Builder-facing):** a Builder emitting an instance must supply, or explicitly record as defaulted, every `content_text` and `content_instance_swap` property. Pill's four become first-class. CF-8 and PB-9 close.

## 12. Migration rules for the accepted Button baseline

Every rule is mechanical unless marked ⚠.

| # | Change | Migration |

| M-2 | C-2 | `rowsAxis`/`columnsAxis` strings → `{kind: "variant_property", propertyKey: <string>, orderedValues: <canonicalOptions of that property>, orderingRule: "declared_variant_option_order"}`. Buttons' axes are all real VARIANT properties, so this is total. |

New contracts must supply the artifact. |
| M-5 | C-5 | ⚠ `documentedPairingCount: 100` → `coverageMetrics[]`. Which metric it is cannot be inferred from the baseline. Migrate to `{metric: "matrix_cells", value: 100, provisional: true}` and **flag for owner confirmation**. |

| M-7 | C-7 | `collectionName`/`collectionId`/`modes` → `collections[0]` with `themeVarying: true`. Buttons' `boundVariableId` values are dropped into `variablesUsedByDescendants[]` with `exhaustive: false`. |
| M-8 | C-8 | `treatmentLabel: "<string>"` → `{kind: "set_identity", label: "<string>"}`. Total for Buttons. |
| M-9 | C-9 | `role` derived from `type`: VARIANT→`variant_axis`, TEXT→`content_text`, INSTANCE_SWAP→`content_instance_swap`, BOOLEAN→`boolean_toggle`. `nonVariantPropertyCoverage: []`. |
| M-10 | C-10 | No change — unscoped entries keep applying to all. |
| M-11 | C-11 | No change — Buttons already passes. |

A migration script must be **idempotent** and must emit a report naming every ⚠ item requiring owner input.
